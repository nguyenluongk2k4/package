# AGENTS.md

This file is a migration handoff for future Codex sessions working on this project.

## Project Summary

This is a Next.js App Router application for **Sac Co Do**, a Vietnamese cultural tourism/passport experience around Ninh Binh. It began from a travel/tour booking template, but the active product is now a custom public site plus admin CMS for:

- a physical/digital passport journey,
- six station check-ins,
- AR guide/model experiences,
- souvenir/product pages,
- user progress, cart, photobooth, and AR session records,
- Firebase-backed content management.

The project is JavaScript-only React/Next. There is no TypeScript source, no lint script, and no automated test suite yet.

## Architecture

- **Framework:** Next.js `16.2.6`, React `19.2.6`, App Router under `app/`.
- **Routing:** Public pages are implemented as route folders in `app/`, usually delegating to components in `components/sac-co-do/`.
- **Global providers:** `app/layout.jsx` wraps the app in `FirebaseAuthProvider`, `ToastProvider`, and `ScrollReveal`.
- **Styling:** Most custom styling lives in `app/globals.css`. Public template assets and legacy CSS/JS remain in `public/assets` and `public/gowilds`.
- **Static fallback data:** `data/sac-co-do.js` contains stations, product/package data, hero slides, navigation, gallery, and fallback public content.
- **Firebase client layer:** `lib/firebase/` initializes Firebase Auth/Firestore, reads fallback/public catalog data, writes admin documents, and saves user journey data.
- **Cloudinary:** `lib/cloudinary/client.js` performs unsigned client uploads for admin media and user photobooth images.
- **Admin CMS:** `components/admin/` contains the admin shell, dashboard, collection managers, form fields, sidebar/header, and user overview. Routes are under `app/admin`.
- **AR:** `components/sac-co-do/WebArViewer.jsx` uses `<model-viewer>` loaded from Google CDN in `app/layout.jsx`. AR assets are served from `public/ar`.
- **Deployment:** Configs exist for Vercel (`vercel.json`, `.vercelignore`) and Firebase Hosting/Firestore rules (`firebase.json`, `firestore.rules`). Vercel is the apparent primary app hosting path.

Important route groups:

- `/`: home.
- `/san-pham`, `/san-pham/[productId]`: products.
- `/hanh-trinh`, `/hanh-trinh/[dia-diem]`: journey map/details.
- `/checkin/[tram-id]`: station check-in flow.
- `/ho-chieu`, `/kich-hoat`, `/cua-toi`, `/gio-hang`, `/photobooth`, `/phan-thuong`: passport/account utility flows.
- `/dang-nhap`: customer login.
- `/admin`, `/admin/stations`, `/admin/products`, `/admin/ar-characters`, `/admin/users`, `/admin/login`: admin CMS.

## Important Decisions

- Public station/product data falls back to `data/sac-co-do.js` when Firebase is missing, empty, or unavailable.
- Public Firebase reads only show published documents; archived/draft records are filtered out of public views.
- Admin access uses Firebase Auth plus an `adminUsers/{uid}` Firestore document with `active: true` and a role.
- Customer auth supports email/password and Google; admin login is intended to be email/password only.
- Firestore rules enforce admin writes for `stations`, `products`, and `arCharacters`, and user-owned access for nested user data.
- Cloudinary uploads use unsigned presets for v1 CMS convenience. Keep the preset scoped/limited in Cloudinary.
- AR files need correct headers. `next.config.js` sets content types and CORS for `/ar/*.glb` and `/ar/*.usdz`.
- True mobile AR requires HTTPS. Desktop and HTTP local URLs are only preview/fallback experiences.
- `reactStrictMode` is disabled in `next.config.js`, likely to avoid double-running client effects in AR/Firebase-heavy flows.
- `initializeFirestore` uses `experimentalForceLongPolling: true` and `useFetchStreams: false`, likely for browser/network compatibility.

## Coding Conventions

- Use `.jsx` for React components and `.js`/`.mjs` for plain modules/scripts.
- Keep page route files thin; most UI belongs in `components/sac-co-do/` or `components/admin/`.
- Use named exports for shared data/functions and default exports for page/component entry points.
- Client-only interactive components begin with `"use client"`.
- Use Firestore helper functions in `lib/firebase/` instead of duplicating Firebase setup.
- Use local fallback data when user-facing pages must continue without Firebase.
- Admin resource documents follow the shape in `components/admin/adminData.js`.
- IDs/slugs are generated by `createId`/`slugFrom`; be careful with Vietnamese d-with-stroke normalization.
- Keep Vietnamese UI text valid UTF-8. Some terminal commands may display mojibake, so verify in an editor/browser before assuming file contents are corrupt.
- Existing admin UI favors compact operational screens, not marketing layouts.
- Existing public UI uses Vietnamese cultural tourism language and a premium heritage feel.
- Avoid large unrelated refactors; there is a lot of legacy template asset surface in `public/`.

## Build And Run Commands

- Install dependencies: `npm install`
- Dev server: `npm run dev`
- Dev server on LAN: `npm run dev:host`
- HTTPS dev server for mobile AR testing: `npm run dev:https`
- Production build: `npm run build`
- Production start: `npm run start`
- Seed Firestore/admin user: `npm run firebase:seed`

Current verification:

- `npm run build` passes. It prerenders 34 app routes and SSG paths for stations/products.

There is currently no configured command for:

- `npm test`
- `npm run lint`
- type checking beyond what Next runs during build

Note: this Windows environment prints a recurring PowerShell profile warning because `fnm` is not installed. It does not block the build.

## Data Model

Primary Firestore collections:

- `adminUsers/{uid}`: admin authorization metadata.
- `stations/{stationId}`: station cards/detail/gallery/map/AR guide/publish status.
- `products/{productId}`: product list/detail fields and optional 3D model config.
- `arCharacters/{characterId}`: GLB/USDZ/poster/animation/default character config.
- `users/{uid}`: user profile metadata.
- `users/{uid}/cart/{itemId}`
- `users/{uid}/journeyProgress/{stationId}`
- `users/{uid}/photoboothPhotos/{photoId}`
- `users/{uid}/arExperiences/{sessionId}`

The seed script writes stations/products from `data/sac-co-do.js`, a default AR character, and optionally an admin user.

## Known Bugs And Risks

- Some PowerShell reads display Vietnamese text as mojibake. `rg` and browser rendering show many strings correctly, but encoding should be audited before migration.
- `createId` and `slugFrom` replace a mojibake d-with-stroke sequence instead of the normal lowercase Vietnamese d-with-stroke character; slug generation for Vietnamese text should be verified and fixed if needed.
- There is a typo-like asset path: `/assets/ic-trash'.svg` in `components/admin/CatalogManager.jsx`. The file exists, but the apostrophe in the filename is brittle.
- Several admin strings still appear mojibake in terminal output. The admin design brief explicitly calls out that Vietnamese text must render correctly.
- The app logs many Firebase auth debug messages in production client code.
- Admin archive does not ask for confirmation.
- JSON editor fields silently fall back on parse failure instead of surfacing validation errors.
- Cloudinary unsigned upload is convenient but should be constrained by preset folder/type/size limits.
- AR flow depends on external CDNs for `model-viewer`, background music, confetti, and an Unsplash fallback image.
- True AR cannot be fully tested over plain local HTTP; use HTTPS/mobile device testing.
- Large legacy template payloads under `public/assets` and `public/gowilds` may inflate repo/deploy size.
- No automated test coverage exists for critical flows such as auth, admin saves, check-in stamping, or build-time route generation.

## Migration Notes

- Bring `.env.example`, `firestore.rules`, `firebase.json`, `vercel.json`, and `next.config.js` with the app.
- Do not commit `.env.local` or service account secrets.
- Preserve `public/ar` asset paths unless updating Firestore/default model references at the same time.
- If moving to a clean repo, consider adding `.nvmrc`/Node version documentation and removing committed build artifacts such as `.next`.
- After migration, run `npm install`, `npm run build`, then seed Firebase with `npm run firebase:seed` only after env/secrets are configured.
